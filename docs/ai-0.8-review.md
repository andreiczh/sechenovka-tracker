# Краткая сводка перед приёмом · 0.8

23 октября 2026. Учебный прототип, только вымышленные данные.

## Что реализовано

В закрытом кабинете психиатра появился запрос `POST /api/clinic/patients/:id/ai-summary`. Он принимает только ID эпизода и ревизию исходных данных. Данные для внешнего сервиса сервер получает из своей БД после проверки входа и согласия на передачу профиля в кабинет.

Модель не пишет медицинские утверждения. Она возвращает JSON с двумя списками: разрешённые ID наблюдений и разрешённые ID вопросов к беседе. Сервер проверяет схему, длины, отсутствие повторов и принадлежность каждому списку. Все показываемые числа, даты и фразы берутся из серверных шаблонов и проверенных полей. Это ограниченная задача отбора и приоритизации; не свободный клинический анализ текста.

Независимо от ответа модели добавляются отдельные сведения о безопасности, незавершённых анкетах, пропущенных днях и давности при необходимости. Нулевой сон и неизвестный сон различаются. Уменьшение баллов не называется выздоровлением или эффектом лечения. Разница PHQ-9 и GAD-7 рассчитывается обычным кодом.

Имена, код профиля, Telegram ID, случайный ID эпизода, свободные заметки, цель пациента и внутренняя запись врача поставщику не передаются. Длительность включается только из утверждённого списка вариантов. Врач должен отдельно читать исходные заметки и уточнять анамнез: такой модуль не анализирует произвольный медицинский текст.

## Провайдеры и фактическая проверка

- Groq: `/home` вернул `Access denied. Please check your network settings` во встроенном браузере; Safari не завершил загрузку. Пользователь сообщил, что тоже не может войти после регистрации. Ключ Groq не извлечён, не изменён и не отозван. Это подтверждение проблемы доступа, а не установленная причина блокировки всего сервиса.
- GitHub Models: исключён после проверки официального объявления о полном закрытии 30 июля 2026. Старые руководства о бесплатном API неприменимы. [Официальное объявление](https://github.blog/changelog/2026-07-01-github-models-is-being-fully-retired-on-July-30-2026/).
- OpenRouter: сайт и публичный API каталога доступны; через обычный вход GitHub открыт существующий аккаунт. В каталоге на момент проверки 17 моделей с нулевой ценой ввода и вывода. Выбран ограниченный `dots-studio/dots-3-note-preview:free`, поддерживающий структурированный вывод. После подтверждения пользователя создан отдельный ключ «Sechenovka synthetic demo»: срок до 23.10.2027, денежный лимит $0. API подтвердил Free-аккаунт и 50 доступных запросов/сутки. Живой запрос Dots вернул проверенный JSON за 2387 мс: 973 входных и 37 выходных токенов, стоимость $0, reasoning_tokens=0. Liquid исключён: обязательное рассуждение давало задержки и неполный ответ при небольшом лимите.
- Kilo: официальная документация допускает анонимный бесплатный API, первые обращения с Mac завершились тайм-аутом. После предпочтения IPv4 каталог стал доступен; тест Liquid всё равно занял 25,7 с и исчерпал бюджет на рассуждение, Xing вернул upstream 429. В этом релизе не используется. [Документация](https://kilo.ai/docs/gateway/authentication).

У OpenRouter Free заявлены 50 запросов в сутки и 20 в минуту на аккаунт. Лимит общий для его ключей; другие проекты могут израсходовать часть квоты. Бесплатные модели и доступность их поставщиков меняются. [Условия бесплатных моделей](https://openrouter.ai/blog/tutorials/how-to-get-the-lowest-cost-llm-inference-on-openrouter/), [каталог](https://openrouter.ai/api/v1/models).

Нельзя считать доступность сайта доказательством доступности inference или доступа у всех российских операторов. Запросы приложения выполняет сервер Render; пациент не обращается к внешнему API из браузера. Медицинские данные настоящих людей для этого бесплатного стенда не разрешены.

## Надёжность и расходы

Один черновик на версию данных, отдельный кэш в врачебном workspace. При смене данных, модели, провайдера или промпта он устаревает. Результат не меняет диагноз, маршрут, запись врача или подтверждённый план пациента.

Лимиты приложения: 20 попыток в сутки, пауза 20 секунд между новыми запросами. Счётчик и блокировка повторного запроса хранятся в общей БД и работают при перекрытии серверных копий. Кэш не расходует квоту. Ошибочная попытка учитывается, автоматических повторов нет.

У OpenRouter разрешена только конкретная бесплатная модель. `max_price` ограничивает ввод/вывод нулём; `allow_fallbacks=false`, `require_parameters=true`, `data_collection=allow` только в запросе с синтетическими фактами. Изначальный `deny` исключил бесплатный endpoint, поэтому эту проверку не выдаём за успешную. Бесплатный поставщик может сохранять запросы и использовать их для обучения; это отражено в интерфейсе. Общие privacy-настройки аккаунта не менялись. Нет перехода на платную модель и изменения настроек оплаты аккаунта.

Вызов поставщика выполняется вне транзакции и блокировки пациента. После ответа повторно проверяются врачебный сеанс, согласие, эпизод, ревизия и ID задачи. Изменившийся или отключённый профиль не получает старый результат. Тайм-аут 22 секунды; ошибка/429 не отключают полную сводку, дневник и анкеты. Ключи, текст ответов и заметки не записываются в обычные логи; остаются модель, версия промпта, время, статус и расход токенов.

## Проверки

Автоматические проверки покрывают отсутствие идентификаторов и свободного текста во внешнем запросе; невозможность новых чисел/лекарств в ответе модели; обязательную безопасность; null/0; ошибки JSON, 400/401/403/429/500; кэш; дневной лимит; гонку двух запросов; изменение данных во время генерации; отзыв входа и согласия; отделение от плана пациента; запрет платной модели и маршрутизации.

Обычный прогон: 70 passed, 1 PostgreSQL opt-in skipped; отдельно PostgreSQL 1 passed. Первый отдельный PostgreSQL-прогон с Mac завершился сетевым `ECONNRESET`. Повтор с `--dns-result-order=ipv4first` прошёл за 69,2 с: TLS, rollback, конкурирующие записи, сохранность плана и ИИ-черновика после перезапуска, отсутствие черновика у пациента. На сервере и локально задано предпочтение IPv4. Живой provider-вызов прошёл; публичный сценарий фиксируется после размещения.

## Критическая проверка решения

1. **Сильная версия идеи.** Уменьшить время подготовки психиатра, сохранив проверяемость каждого наблюдения и самостоятельность его решения.
2. **Что подтверждено.** Числа и фразы серверные, модель выбирает только из списка; сырой текст и идентификаторы не выходят; гонки и основные отказы покрыты локальными тестами.
3. **Риски.** Небольшая модель может неудачно расставить приоритеты или выбрать слабые вопросы. Дневник неполон, анамнез не собран. Бесплатный provider может отказать без SLA. Отсутствие свободного текста уменьшает полноту сводки.
4. **Допущения.** Все входные сведения вымышлены; врач просматривает исходные данные; пригодность к реальной клинической работе не заявляется.
5. **Что проверить.** Живой бесплатный inference, сохранность после deploy, UI и исходные ссылки, расход квоты. Для следующего этапа — независимое врачебное сравнение приоритетов на размеченных случаях и отдельное решение по настоящим данным.
6. **Уверенность.** 95% в ограниченной технической архитектуре по автоматическим и живым API-проверкам; клиническая полезность не оценена. Это не процент медицинской точности.
