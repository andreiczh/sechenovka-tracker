# Размещение учебного демо на alwaysdata Free

Подготовлено 23.10.2026 для версии 0.4.0. Проект пока работает локально; аккаунт и удалённый репозиторий не создавались, публикация не выполнялась.

## Что готово

- Node.js 24, без устанавливаемых зависимостей и отдельной сборки фронтенда.
- `HOST`/`IP`, `PORT`, `PUBLIC_ORIGIN`, `DATA_DIR`; проверка настроек до запуска.
- Точный разрешённый публичный Host и HTTPS Origin, HttpOnly/SameSite/Secure cookie. Произвольные домены и межсайтовые записи отклоняются.
- `/healthz` не создаёт тестовый профиль; серверные ошибки пишутся структурированно без ответов, заметок, cookies и секретов.
- Постоянный SQLite за пределами каталога кода; отдельная команда согласованной резервной копии, учитывающей WAL.
- Защищённый HTTP-запуск демонстрационных напоминаний из Scheduled Tasks. Отдельный постоянно работающий Services-процесс не нужен.
- Архив для загрузки, проверка работоспособности и GitHub Actions для тестов. Автоматическая публикация не включена.

| Адрес | Состояние |
| --- | --- |
| `/` | Памятка ВОП |
| `/patient/` | Приложение пациента |
| `/bot/` | Браузерный симулятор диалога |
| `/psychiatrist/` | Кабинет психиатра: список, карточка, динамика, сводка и демоплан |

Это синтетическое учебное демо. Проверяемой Telegram-идентичности, настоящей доставки в Telegram и реальной врачебной авторизации пока нет. Кабинет работает с тестовой привязкой в одном браузере. Все три интерфейса размещаются одним Node-процессом на одном адресе и разных путях, без трёх отдельных тарифов. Подготовка хостинга не означает готовность работать с реальными медицинскими данными.

## Тариф и доступ из РФ

[Официальный Free](https://help.alwaysdata.com/en/docs/admin-billing/billing/public-cloud-prices/): 1 GB диска, 256 MB RAM, 1/4 CPU, резервные копии за 3 дня; некоммерческое использование, только адрес аккаунта `alwaysdata.net`, без отдельных Services. Диск общий для кода, баз и почты. [Node.js 24 поддерживается](https://help.alwaysdata.com/en/docs/web-hosting/languages/nodejs/configuration/).

Без карты профиль остаётся в [restricted mode](https://help.alwaysdata.com/en/docs/admin-billing/profile/restricted-mode/): HTTP проходит более строгие фильтры, возможны задержки. Это не равнозначно запрету бесплатного аккаунта. Регистрацию и доступность Scheduled Tasks в конкретном новом аккаунте нужно подтвердить при создании.

Прямой HTTPS из текущей сети без VPN и прокси проверен 23.10.2026: страна выхода RU, интерфейс en0, все VPN отключены во время запроса. Главный сайт, панель, документация и два публичных сайта на `alwaysdata.net` вернули 200, 0,58–1,02 с. С VPN также 200; исходное VPN-подключение восстановлено. Это подтверждение текущего доступа из одной российской сети, не гарантия для каждого оператора. Тариф чужих сайтов независимо не установлен. Free-аккаунт не регистрировался.

Доказательства: `test-results/fixes-2026-10-23/alwaysdata-network-direct.json`, `alwaysdata-network.json`, `vpn-restoration.json`. Публичные IP и реквизиты подключения не сохранялись.

## Первый запуск

1. Зарегистрировать личный Free-аккаунт на [alwaysdata](https://www.alwaysdata.com/en/offers/), подтвердить email. Не выбирать платный Plus под видом бесплатного первого месяца. Включить SSH/SFTP; в **Environment → Node.js** выбрать **24**.
2. Собрать архив локально: `npm test`, `npm run preflight`, `npm run package`. Готовый файл — `dist/sechenovka-v0.4.0.tar.gz`. Он не содержит `.data`, заполненного `.env`, Git, `node_modules` и скриншотов тестов.
3. Загрузить архив в домашний каталог аккаунта через SFTP. По SSH выполнить:

```sh
mkdir -p sechenovka/current sechenovka/shared/data
tar -xzf sechenovka-v0.4.0.tar.gz -C sechenovka/current
cp sechenovka/current/.env.example sechenovka/shared/production.env
chmod 600 sechenovka/shared/production.env
```

4. Отредактировать **серверный** `production.env`: заменить `ACCOUNT` в домене и абсолютном `DATA_DIR`. Оставить `NODE_ENV=production`, `DEMO_MODE=true`, сначала `REMINDER_SCHEDULER=off`. Не переносить файл в `public/` и не отправлять его в Git. `HOST`/`IP` и `PORT` предоставляет конфигурация сайта, вручную ставить туда localhost:4173 не нужно.
5. В **Web → Sites → Add → Node.js** указать адрес `ACCOUNT.alwaysdata.net`, рабочий каталог `/home/ACCOUNT/sechenovka/current` и команду ниже, предварительно заменив `ACCOUNT`. В окружении сайта также установить `NODEJS_VERSION=24`: значение внутри env-файла само по себе не переключает оболочку выбора версии Node.

```sh
node --env-file=/home/ACCOUNT/sechenovka/shared/production.env /home/ACCOUNT/sechenovka/current/server.mjs
```

6. Включить принудительный HTTPS в настройках сайта. Команда должна слушать IP/HOST и PORT, указанные панелью; сервер читает их автоматически. Проверить запуск без создания пациентских записей:

```sh
node --env-file=/home/ACCOUNT/sechenovka/shared/production.env /home/ACCOUNT/sechenovka/current/scripts/preflight.mjs
node --env-file=/home/ACCOUNT/sechenovka/shared/production.env /home/ACCOUNT/sechenovka/current/scripts/healthcheck.mjs
```

7. Пройти тестовую анкету, перезапустить сайт через панель и убедиться, что запись сохранилась. Затем проверить HTTPS-адрес с телефона и из РФ с VPN/без VPN, включая загрузку файлов и сохранение ответа. Проверка localhost этого не заменяет.

## Напоминания на Free

Реальный Telegram ещё не подключён: этот механизм записывает сообщения только в демонстрационный диалог.

1. Сгенерировать новый `CRON_SECRET` на сервере, сохранить в `production.env`, не пересылать в чат. Для генерации подходит `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.
2. Поменять `REMINDER_SCHEDULER=external`, перезапустить сайт.
3. В **Advanced → Scheduled Tasks** создать задачу раз в минуту с командой ниже; доступность такой частоты подтвердить в аккаунте:

```sh
node --env-file=/home/ACCOUNT/sechenovka/shared/production.env /home/ACCOUNT/sechenovka/current/scripts/run-reminders.mjs
```

Задача вызывает основной сервер по HTTPS с секретом в заголовке. Она не открывает вторую копию SQLite и не пишет состояние параллельным процессом. Отправки идемпотентны по дате, времени и заданию. Позднее пропущенные сообщения не рассылаются пачкой.

[Scheduled Tasks](https://help.alwaysdata.com/en/docs/web-hosting/tasks/) запускаются внутри указанной минуты, журнал — `admin/logs/jobs/`. Отдельные [Services доступны только на платных тарифах](https://help.alwaysdata.com/en/docs/web-hosting/services/). Не запускать на Free отдельный бесконечный polling-процесс Telegram.

## Обновления без потери данных

Для первого запуска достаточно архива. Для регулярных правок предпочтителен приватный GitHub-репозиторий с этим каталогом приложения в корне и копия на хосте в `sechenovka/current`.

- Локально: правки → `npm test` → `npm run preflight` → commit/push.
- На хосте, если `current` получен через `git clone`: `git pull --ff-only`, затем **Restart** в Web → Sites и запуск `healthcheck`.
- Если первая установка сделана из архива, обновлять новым проверенным архивом в каталог кода. Для перехода на Git сначала сделать резервную копию и подготовить отдельную копию кода; команды `git pull` не применяются к распакованному каталогу без `.git`.
- Перед обновлением: `node --env-file=/home/ACCOUNT/sechenovka/shared/production.env /home/ACCOUNT/sechenovka/current/scripts/backup.mjs`. Копия создаётся в `shared/data/backups/` и включает подтверждённые записи WAL. На квоте 1 GB следить за объёмом и сроком хранения копий.
- База и `production.env` остаются в `shared/`, вне кода. Не загружать локальную `.data` поверх действующей базы. Откат кода не должен удалять базу. Изменение формата данных в будущем потребует проверенной миграции.
- `.github/workflows/check.yml` запускает проверки и сборку архива после push/PR. На GitHub workflow пока не выполнялся: удалённого репозитория нет. SSH-автопубликацию подключать после первого успешного ручного размещения; сейчас секретов деплоя и внешних изменений нет.

## Что проверить после регистрации

- Free действительно активирован, email подтверждён, аккаунт не заблокирован антифродом; HTTP-фильтр не препятствует JSON-запросам приложения.
- Node 24 и встроенный `node:sqlite` доступны: `preflight` успешен.
- Scheduled Tasks доступны с подходящей частотой; секрет не отображается в URL/логах.
- Правильные домен, IP/HOST, PORT, HTTPS и Secure cookie; чужой Origin по-прежнему отклоняется.
- Внешняя доступность на российских Wi-Fi/мобильной сети и в настоящем Telegram WebView. До подключения Telegram результат проверки браузерного симулятора не выдавать за проверку бота.
- Нет реальных медицинских данных. Для коммерческого пилота отдельно выбирать тариф, режим доступа и организацию обработки данных.
