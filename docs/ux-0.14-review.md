# Пациентский миниапп: 0.14.0

25 октября 2026. Учебная система, вымышленные данные.

## Изменения

Убрано автоматическое разбиение карточек пациента по высоте. Оно порождало повторяющиеся горизонтальные пункты «1/3, 2/3» и могло отделять кнопку от её пояснения. Пациентские экраны теперь целые; общая рамка не прокручивается, длинная история и раскрытые формы прокручиваются в рабочей области. Защитная ветка в общем viewport-модуле восстанавливает исходные узлы, даже если закешированный старый клиент ещё вызывает прежний механизм. Главный JS и новый CSS имеют номер версии в URL; кеш оболочки обновлён.

Вместо большого вступления — заголовок 30 px по высоте и контекст дня. Шапка 46 px, основная навигация внизу, пять понятных разделов без дублирующих переключателей. На экране «Сегодня» сразу видно текущее задание, основную кнопку и голосовую заметку. Результаты показывают две самостоятельные суммы; длинные объяснения и история раскрываются по запросу. Динамика начинается с графика, пояснения доступны ниже. Информация об анкетах остаётся доступна кнопкой в шапке.

«К приёму» сразу показывает заготовку разговора от первого лица и вопросы врачу, в том числе до завершения анкет. Даты, передача профиля и полный экспорт перенесены в раскрываемые разделы. Итоговые баллы подставляются только из завершённой анкеты. При наличии ответов о безопасности подсказка обсудить их приоритетна; прямые сообщения о безопасности не спрятаны в дополнительных разделах.

## Голос

Нажатие «Записать голосом» открывает инструмент и запрашивает микрофон до ожидания сетевых запросов. Повторная отметка о вымышленности не нужна после принятия учебного режима при входе. Запись не ждёт загрузки Whisper; звук и состояние записи отделены от подготовки текста. Согласие на внешнюю ИИ-обработку остаётся отдельным, врачебное согласие участников не отменено.

У пациента один текст заметки вместо постраничного просмотра отдельных реплик. После остановки доступны прослушивание, исправление и явное сохранение; название и выгрузки находятся в дополнительных действиях. Открытие сохранённой заметки, архива и входящего Telegram-аудио микрофон не включает. Надиктованный текст в поле по-прежнему требует сохранения самой формы. Пояснение места сохранения короткое и расположено рядом с текстом.

## Уже проверено локально

- 138 автоматических проверок: 137 прошли, 0 ошибок, 1 PostgreSQL opt-in пропущен.
- Через браузер последовательно пройдены 9 PHQ, 7 GAD и 3 контекстных вопроса. Сохранены ожидаемые суммы 8/27 и 7/21, ненулевой ответ на пункт 9 в этом сценарии не использовался.
- На мобильном экране 390×844 начальное задание и кнопка записи видны без перехода между частями; DOM не содержит viewport-controls или скрытых частей старой пагинации. Заголовок «Сегодня» занимает 30 px.
- Контрольный аудиофайл действительно распознан Whisper base q8 в браузере: 23 слова, одна ошибка — пропуск союза «и». После нормализации регистра, пунктуации и «ё/е» WER = 1/23 = 4,35%. «Ничего не принимаю» сохранено. Текст проверен и сохранён через интерфейс.
- В Safari получен настоящий сигнал микрофона, шёл таймер записи и отработала остановка. Длинная акустическая проба с воспроизведением через динамик и фоновыми репликами дала ошибки, включая искажение фразы о трудностях работы. Эту пробу нельзя выдавать за высокую точность клинического распознавания; её текст не опубликован пациенту или внешнему ИИ.

Один чистый синтетический файл не валидирует распознавание живой русской речи. Whisper base может ошибаться в отрицаниях, названиях и при фоновом шуме. Пользователь должен сверить текст с аудио перед сохранением; аудиозапись не выставляет баллы и не становится назначением. Качество распознавания не следует из успешных тестов интерфейса.

## Стек обычным текстом

Интерфейсы написаны на HTML, CSS и JavaScript с ES-модулями. Для адаптивной компоновки используются Grid, Flexbox и запросы к размеру экрана; графики рисуются SVG. У сайтов ВОП и пациента есть PWA-манифесты и Service Worker для кеширования оболочки. Данные API в офлайн-кеш не записываются.

Backend работает на Node.js 24 со встроенным HTTP-сервером. Постоянная база — PostgreSQL в Neon через драйвер pg; локально используется SQLite. Бот и Mini App обращаются к одному движку опросов и общему профилю через Telegram Bot API, webhook и проверку подписанных initData. Кабинет врача имеет отдельную серверную сессию.

Микрофон обслуживают getUserMedia, MediaRecorder, Web Audio API и AudioWorklet. Whisper base через Transformers.js 3.8.1 и ONNX Runtime Web распознаёт звук в браузере. Текстовый ИИ подключён через OpenRouter; используется dots-studio/dots-3-note-preview:free. Он выбирает наблюдения и вопросы из каталога, а для беседы предлагает роли и темы. Медицинские баллы и защитные правила считает серверный код. Размещение — Render, хранение — Neon, код — GitHub, проверки и запуск проверки напоминаний — GitHub Actions.

## Критическое заключение

Основная гипотеза UX — каждое действие видно на одном экране без автоматически нарезанных карточек. Функциональные проверки подтверждают отсутствие прежней пагинации, доступность действий и сохранение значений. Удобство на группе пациентов ещё не измерено. Самое существенное ограничение — точность распознавания живой речи: она требует отдельного набора записей и врачебной проверки. Уверенность в проверенных технических изменениях — 95%; точность клинической расшифровки этим процентом не оценивается.
