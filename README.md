# Трекер Сеченовка

Первая локальная версия: памятка для ВОП, авторский чек-лист и передача ссылки пациенту.

## Запуск

Нужен Node.js 20 или новее. Сборки и установки зависимостей нет:

```sh
npm run dev
```

Адрес: **http://localhost:4173**. Сервер по умолчанию слушает только `127.0.0.1`. Другой порт: `PORT=4174 npm run dev`.

В текущем окружении Codex сервер запущен из этого каталога. Если Node не находится в системном PATH, доступен поставляемый с приложением бинарник:

```sh
/Users/andreich/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node server.mjs
```

## Что работает

- 10 пунктов наблюдений, счётчик, сброс и активация «Нужен тест» при 6 отметках.
- Доступ к следующему экрану по решению врача при любом количестве отметок.
- Отдельные признаки, требующие оценки безопасности; предупреждение сохраняется на экране передачи.
- QR на `https://t.me/sechenov_track_bot`, ссылка и её копирование.
- Объяснение пациенту, копирование текста и ответы на сомнения.
- Белый фон, локальный Golos Text, спокойные зелёные и красные акценты.
- Десктопная и мобильная вёрстка, PWA-манифест, иконки и кеширование памятки для офлайн-доступа.
- Источники и ограничения внутри сайта.

## Границы этой версии

Счётчик **6/10 (60%) — условие демонстрации интерфейса**, не валидированный медицинский порог. Процент не является вероятностью заболевания. Чек-лист не заменяет клиническую оценку, PHQ-9 или GAD-7. Значимые жалобы учитываются независимо от количества отметок.

Анкеты, дневник, кабинет психиатра и серверная интеграция Telegram будут отдельными этапами. Наличие ссылки на бота не означает готовность этих функций. Назначения в этой версии не формируются.

Отметки существуют только в памяти открытой страницы и сбрасываются при перезагрузке. Нет ФИО, полей медицинского свободного текста, аналитики и отправки отметок на сервер. Service Worker кеширует только статические файлы сайта.

Для установки PWA на телефон потребуется HTTPS-размещение. `localhost` относится к устройству, на котором открыт браузер. Установка на реальном iOS/Android в этой итерации не проверена; браузерная адаптация и офлайн-режим проверены.

## Структура

- `public/index.html` — два экрана, источники и инструкция PWA.
- `public/styles.css` — интерфейс и адаптация.
- `public/clinical-data.js` — пункты, источники и чистая функция счётчика.
- `public/config.js` — публичные настройки и URL бота.
- `public/app.js` — взаимодействия без отправки медицинских данных.
- `public/service-worker.js`, `manifest.webmanifest`, `icons/` — PWA.
- `server.mjs` — локальный сервер, обслуживающий только `public/`.
- `tests/checklist.test.mjs` — проверки границы и независимости признаков безопасности.
- `docs/` — источники, ограничения, проверка и промпты для оформления.

В этом репозитории хранятся **только публичный username и URL бота**. Серверный токен здесь не нужен и в клиентский код не добавляется. Реальные секреты следует хранить в окружении серверной части и не публиковать в переписке или Git.

## Проверки

```sh
npm test
```

Браузерный прогон проверяет порог, переходы, сброс, отдельные значимые признаки, копирование, QR независимым декодером, мобильные ширины и офлайн-доступ. Результат первой проверки — `docs/qa-report.md`. Скриншоты и машинный отчёт находятся в игнорируемом `test-results/`.
