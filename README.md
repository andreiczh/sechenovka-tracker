## Подключённый кабинет и компактные интерфейсы

Врачебный вход отделён от профиля пациента. В боте `/doctor` объясняет передачу, `/share` подключает вымышленный профиль, `/unshare` отключает. В Mini App те же действия доступны в «К приёму». Результаты, черновики анкет, дневник и динамика появляются у психиатра; подтверждённая часть плана возвращается пациенту. Поля внутренней записи не передаются.

Врачебный сеанс действует до 12 часов и отзывается при выходе. Для локального кабинета задайте серверный `CLINICIAN_ACCESS_KEY` длиной 24–256 символов. При настроенном Telegram без отдельного override ключ получается серверным HMAC с отдельным назначением от `TELEGRAM_IDENTITY_SECRET`. Его нельзя вычислять в браузере или добавлять в публичную конфигурацию.

Шапки и футеры компактные. Длинные разделы используют страницы с сохранением полей формы. Десктопная памятка ВОП показывает весь чек-лист и безопасность одновременно. Доступный fallback сохраняет содержимое при экстремальном масштабе или высоте.

## Краткая сводка к беседе

В подключённой карточке: **Сводка → Подготовить краткую сводку**. Модель выбирает важные наблюдения и вопросы, а фактический текст формируется сервером из сохранённых значений. У каждого наблюдения есть ссылка на раздел с источником. Безопасность, незавершённые анкеты и пропуски не зависят от выбора модели. Черновик не становится врачебным планом и не отправляется пациенту.

Сервер поддерживает Groq (`GROQ_API_KEY`) и OpenRouter (`AI_PROVIDER=openrouter`, `OPENROUTER_API_KEY`). Для OpenRouter разрешена только `dots-studio/dots-3-note-preview:free`, нулевая цена и отсутствие платного fallback. Значения — только в секретах Render или исключённом из Git локальном `.env.ai`; не в `public/`. Пример локального запуска: `node --env-file=.env.clinician --env-file=.env.ai server.mjs`. Настройки без ключа сохраняют обычную полную сводку.

По умолчанию максимум 20 новых генераций в сутки на весь учебный проект, между ними не менее 20 секунд; готовая версия читается из кэша. После изменения данных черновик помечается устаревшим. Для краткого разбора пациента и сводки перед приёмом передаются только структурированные синтетические факты: имена, коды, Telegram ID, свободные заметки и записи врача исключены. Отдельное структурирование голосового текста 0.10 имеет другой состав передачи, описанный ниже. Тайм-аут и ошибки провайдера не мешают сохранению анкет и дневника.

## Голосовые записи 0.10

- **Пациент:** «Заметка голосом» на главном экране и в дневнике. Запись до 5 минут, файл, просмотр текста, исправление, необязательные темы и вопросы, отдельное сохранение. Кнопка «Надиктовать» в текстовых полях вставляет проверенный текст и не отправляет форму. Сохранённая заметка доступна подключённому учебному кабинету.
- **ВОП:** микрофон в шапке. Можно свернуть запись, отмечать жалобы в памятке и вернуться. Сохраняются выбранные врачом пункты и отдельные опасения. Запись остаётся в рабочем пространстве ВОП: без идентификации пациента она не прикрепляется автоматически к чужому профилю.
- **Психиатр:** микрофон в шапке карточки и раздел «Беседы». Текст и предполагаемые роли, темы, вопросы, контекст пациента, TXT, архив и восстановление. Врачебные беседы приватны; они не публикуются в пациентском плане. Уточнение создаёт новую версию, сохраняя исходную.
- **Telegram:** голосовое или `/voice` открывают работу с записью в Mini App; голос не считается ответом на текущий вопрос PHQ-9/GAD-7. Файл Telegram доступен своему подписанному профилю один час, временно проходит через сервер без записи аудио в БД.

Whisper base выполняется в браузере. При первом использовании нужны около 100 МБ статических файлов, затем они кешируются браузером. Сервер выдаёт их со своего домена из фиксированного списка, проверяя SHA-256; на Render фоновой прогрев начинается после запуска. В холодном экземпляре первая загрузка может занять несколько минут. Аудио с микрофона или локального файла не передаётся серверу и внешнему ИИ. Запись может идти до 60 минут у врача; загружаемый врачебный файл — до 10 минут / 30 МБ. При сворачивании приложения запись приостанавливается; продолжение выполняется явно. Медленное устройство может потребовать пауз.

По отдельному согласию внешнему OpenRouter отправляется **проверяемый вымышленный текст расшифровки**, а также структурированный контекст из системы и ручные отметки ВОП для соответствующего режима. Бесплатный поставщик может хранить текст и использовать его для обучения. Маскирование почты и телефонов не гарантирует обезличивания. Реальные медицинские сведения здесь не использовать. Модель возвращает только ссылки на фрагменты, роли и темы; слова, числа и отрицания не переписываются. Это смысловая гипотеза роли по тексту, не акустическая диаризация. Врач проверяет роли, текст, отрицания и названия.

Ни запись, ни структура не выставляют баллы анкет, диагноз, лекарственное назначение или подтверждённый план. Новая беседа требует актуализировать прежнюю лекарственную проверку. Без ИИ остаются запись, ручное исправление, сохранение и выгрузка. Архивирование обратимо. Аудио хранится в памяти окна до закрытия; его можно скачать отдельно. [Полное техническое, клиническое и правовое ревью 0.10](docs/voice-0.10-review.md), [фактическая проверка Telegram и трёх интерфейсов 0.10.4, включая незавершённую аппаратную приёмку](docs/voice-0.10.4-recheck.md).

## Запуск

Нужен Node.js 24+ с `node:sqlite` (проверено на 24.19.0). Статический интерфейс не требует сборки. Установка серверных зависимостей:

```sh
npm ci --ignore-scripts
npm run dev
```

Адреса: [памятка ВОП](http://localhost:4173/), [Mini App пациента](http://localhost:4173/patient/), [кабинет психиатра](http://localhost:4173/psychiatrist/), [диалог бота](http://localhost:4173/bot/). По умолчанию сервер слушает `127.0.0.1`; публичный режим задаётся серверным окружением. Другой порт: `PORT=4174 npm run dev`.

В текущем окружении Codex сервер запущен из этого каталога. Если Node не находится в системном PATH, доступен поставляемый с приложением бинарник:

```sh
/Users/andreich/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node server.mjs
```

## Пациентский сценарий

- Исходные PHQ-9/GAD-7, по одному вопросу, с точными русскими текстами выбранных форм. Сохраняются ответы, версия, временное окно и контекст.
- Отдельные баллы и понятная расшифровка; нет общего рейтинга, диагноза или назначения по сумме.
- Отдельный вопрос после положительного пункта 9 PHQ-9, памятка помощи и пауза обычного опроса. Кнопка раннего обращения доступна независимо от баллов.
- Дневник: настроение, тревога, сон, влияние на дела и необязательная заметка. Проверка изменений доступна с первого дня; на 14-й — повтор полных анкет. Дополнительная запись дня 0 включается в статистику и график. Старый черновик требует выбора даты.
- История, графики с разрывами на пропусках, таблица, описательная статистика и полнота данных.
- Дата контакта со слов пациента, главный вопрос и сводка для скачивания/копирования. Отметка состоявшегося приёма завершает напоминания этого этапа.
- Локальный диалог с нижней клавиатурой и текстовыми ответами. Можно начать в Mini App, продолжить в боте и вернуться; данные общие для cookie-сессии.
- 1–3 времени напоминаний и IANA-пояс. После выполнения основного задания его напоминания отменяются. Дополнительный дневник не закрывает обязательный повтор анкет. Локальный планировщик сохраняет журнал в SQLite.
- Присланные пользователем логотип, заставка и PWA-иконки.

Чтобы быстро увидеть заполненную историю: **«Тестовые данные» → «Загрузить пример за 13 дней»**. Там же можно сдвигать демонстрационную дату и начать заново. В разделе напоминаний кнопка проверки перемещает демо к ближайшей доставке. Сообщение появится в локальном диалоге.

## Границы этой версии

Счётчик **6/10 (60%) — условие демонстрации интерфейса**, не валидированный медицинский порог. Процент не является вероятностью заболевания. Чек-лист не заменяет клиническую оценку, PHQ-9 или GAD-7. Значимые жалобы учитываются независимо от количества отметок.

Анкеты и дневник работают через собственный API. При настройке серверных секретов включаются отправка сообщений Telegram и проверка initData. Вход в учебный кабинет защищён отдельным ключом и сеансом; это не проверка личности врача и не готовая медицинская информационная система. Автоматические назначения не формируются. Есть ограниченная врачебная справка Авиандра и структурирование вымышленного голосового текста, с описанными выше границами. Независимый клинический review, юридическая квалификация функций/обработки, архитектура для реальных медицинских данных и проверка прав на коммерческое использование русских форм остаются открытыми.

Отметки **чек-листа ВОП** существуют в памяти страницы; при явном сохранении/структурировании беседы они включаются в её контекст. **Пациентские вымышленные ответы** и проверенные расшифровки сохраняются локально в `.data/demo.sqlite` (исключено из Git), а при заданном `DATABASE_URL` — в отдельной PostgreSQL. Код и ответы хранятся раздельно. Поля заметок предназначены только для тестовых сведений. Сторонняя веб-аналитика не подключена; вымышленные сведения отправляются ИИ только по явному действию с согласием для соответствующего сценария. При использовании бота вопросы, ответы и голосовые проходят через Telegram; в журнале доставки отмечаются только подтверждённые отправки. Service Worker кеширует только статический интерфейс, не API и ответы пациента. При недоступности API новые ответы не сохраняются; интерфейс показывает ошибку и позволяет повторить действие.

Для Telegram и доступа с телефона потребуется доступный HTTPS-адрес. `localhost` относится к устройству, на котором открыт браузер. Установка на реальном iOS/Android и в Telegram не проверена. Памятка ВОП доступна офлайн; Mini App требует работающего API.

## Структура

- `public/index.html` — два экрана, источники и инструкция PWA.
- `public/styles.css` — интерфейс и адаптация.
- `public/clinical-data.js` — пункты, источники и чистая функция счётчика.
- `public/config.js` — публичные настройки и URL бота.
- `public/app.js` — взаимодействия без отправки медицинских данных.
- `public/service-worker.js`, `manifest.webmanifest`, `icons/` — PWA.
- `public/patient/` — приложение пациента и собственный PWA-манифест.
- `public/psychiatrist/` — список, шесть разделов карточки, черновик и подтверждение плана.
- `lib/clinician.mjs` — синтетические случаи, агрегаты, сводка, версии врачебной записи и границы пациентского плана.
- `public/bot/` — симулятор диалога Telegram.
- `public/shared/` — формы, шкалы и клиент API.
- `lib/patient.mjs`, `lib/time.mjs` — общая модель двух интерфейсов, задачи и напоминания.
- `lib/store.mjs` — SQLite; `lib/postgres-store.mjs` — PostgreSQL с TLS и транзакциями; `lib/telegram-adapter.mjs` — ReplyKeyboardMarkup без отправки.
- `server.mjs` — локальный статический сервер и `/api/state`, `/api/action` с проверкой входов и ревизий.
- `tests/checklist.test.mjs` — проверки границы и независимости признаков безопасности.
- `docs/` — источники, ограничения, проверка и промпты для оформления.

В этом репозитории хранятся **только публичный username и URL бота**. Серверный токен хранится только в исключённом из Git окружении, в клиентский код не добавляется. Реальные секреты следует хранить в окружении серверной части и не публиковать в переписке или Git.

- Шесть профилей: пять подготовленных вымышленных случаев и текущий пациентский профиль этого браузера. Поиск по имени/коду, фильтры, сортировка и сведения о полноте/давности данных.

- Анкеты: исходный/повторный результат, все 16 ответов, даты, окно и версия. Черновик с пропусками не становится нулевым результатом.
- Дневник: календарь влияния на дела, выбор дня, заметки, время внесения, пропуски и ретроспективные записи.
- Динамика: отдельные шкалы PHQ-9/GAD-7, настроение, тревога, сон и обычные дела; разрывы, недельные агрегаты и знаменатели, таблица/CSV.
- Контекст, лекарства и новые явления: самоотчёт со статусом проверки. В примере выполнения плана 8 выполненных, 2 пропуска и 4 неизвестных; схема к препарату не привязана.
- Врачебная запись: черновик, отдельное подтверждение, история версий и журнал показов разделов/действий. Отметка просмотра не снимает вопросы безопасности.
- Подтверждённый план профиля ТС-LOCAL появляется в Mini App → «К приёму». Внутренние клиническая запись и уточнение безопасности в пациентский ответ API не включаются. После сброса профиля начинается новый эпизод, прежний план не переносится.
- Сводка: копирование, TXT, печать/сохранение PDF средствами браузера; CSV дневника. Полная врачебная сводка содержит внутреннюю запись и не предназначена для автоматической отправки пациенту.

Связь в демо определяется cookie этого браузера. Это не модель авторизации для реальной клиники; профили разных браузеров изолированы. Новая таблица SQLite создаётся без удаления прежней пациентской базы; резервная копия включает обе таблицы. Все ресурсы кабинета отдаются с того же сайта; внешние библиотеки интерфейса не загружаются.
